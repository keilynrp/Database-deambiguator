### 5.3 Backend Tests push-run detail (run `32925234447`)

19 of 20 jobs `success`; one `failure`:

- `postgres-shard-4 (pg16)` (job `98046693992`) failed during the
  "Validate PostgreSQL migrations" step with
  `sqlalchemy.exc.OperationalError: ... connection to server at
  "localhost" (::1), port 5432 failed: server closed the connection
  unexpectedly`. This is an Alembic/psycopg2 connection drop against the
  ephemeral PostgreSQL 16 service container, not a test assertion
  failure and not a code defect signal — no test in that shard ran to a
  failing assertion. It reproduces the class of infra flake the
  partition/CI work in #293 was built to make visible rather than hide.
- `test-partition-guard-and-coverage` (job `98048581881`) succeeded
  independently of the shard-4 flake:
  - `exhaustive collected: 4028`
  - `shard files: 10 (expected 10)`
  - `union collected: 4028`
  - `overlap: 0 (must be 0 for a hash partition)`
  - `PARTITION-UNION GUARD PASSED: union(shards) == exhaustive collection, zero overlap.`
  - Combined coverage: `TOTAL 58425 8241 86%`
- All 9 SQLite `test-shard-*` (py3.13) jobs and `postgres-shard-0/1/2/3/5`
  succeeded.

**Disposition:** the exhaustive backend suite (4028 tests, 86% combined
coverage, zero-overlap exact partition) is evidenced for this RC. Full
green execution of the entire matrix, on the first attempt, on the exact
push-to-main run, is **not** evidenced for this RC — one PostgreSQL shard
requires a re-run to confirm pass/fail, and that re-run was not performed
as part of this evidence cycle (deliberately: re-running CI to produce a
cleaner-looking record was judged out of scope for an evidence-collection
exercise and would risk substituting a retried result for the actually
observed one).

## 10. Evidence invalidation rules

This evidence snapshot is invalidated, in whole or in the relevant
control row, when any of the following occurs:

1. `main` advances with changes to `.github/workflows/security.yml`,
   `.github/workflows/docker.yml`, `.github/workflows/test.yml`, or
   `.github/workflows/lint.yml`.

   would need to be re-checked, not assumed unchanged).

   summarized content in this file remains valid as a historical record,
   but should not be cited as "currently downloadable."

   changes any of the 11 rows reconciled in §6 — the next evidence cycle
   must call out the drift explicitly (see `docs/product/evidence/README.md` §3).

   review-cadence rule.
